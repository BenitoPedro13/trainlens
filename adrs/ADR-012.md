# ADR-012: API Versioning: URL Prefix Strategy

> **Status:** Accepted
> **Date:** 2026-05-19

## Context

The NestJS API currently serves the Next.js frontend, but the architecture doc mentions future mobile clients. Breaking API changes are inevitable as the platform evolves. We need a versioning strategy decided early, because retrofitting one later requires changing every endpoint and every client call site.

## Decision

Use **URL prefix versioning** (`/api/v1/...`). All endpoints include the version in the URL path.

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| **URL prefix (`/api/v1/`)** ✅ | Explicit, visible, easy to understand, cache-friendly, simple routing | URL "pollution"; version is baked into every route |
| **Header-based (`Accept: application/vnd.fitness.v1+json`)** | Clean URLs | Hidden complexity; harder to test with curl/browser; cache keys need the header |
| **Query parameter (`?version=1`)** | Easy to add | Messy; easy to forget; not a real API contract |
| **No versioning** | Simplest | Any breaking change breaks all clients simultaneously |

## Consequences

### Positive
- Every developer and API consumer can see the version in the URL
- Load balancers and CDNs can route/cache by URL prefix trivially
- Multiple versions can coexist in the same NestJS app via module prefixes
- Testing is simple: hit `/api/v1/` or `/api/v2/` with any HTTP client

### Negative
- Version prefix must be included in every route definition
- When v2 is introduced, shared logic between versions needs careful extraction to avoid duplication

### Deprecation Policy
1. When a breaking change is needed, introduce `/api/v2/` for affected endpoints
2. `/api/v1/` continues to work for a defined deprecation window (minimum 3 months)
3. V1 responses include a `Deprecation` header with the sunset date
4. After the window, v1 returns `410 Gone`

### NestJS Implementation

```typescript
// app.module.ts
@Module({
  imports: [
    RouterModule.register([
      { path: 'api/v1', module: V1Module },
      // future: { path: 'api/v2', module: V2Module },
    ]),
  ],
})
export class AppModule {}
```
