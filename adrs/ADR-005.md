# ADR-005: Authentication: Auth.js (NextAuth v5) + NestJS JWT Guard

> **Status:** Accepted
> **Date:** 2026-05-19

## Context

The platform requires two distinct auth concerns: (1) user authentication (login/signup) and Strava OAuth2 dance (including token refresh), and (2) API authentication so the NestJS backend can verify requests from the frontend. These are best handled by different layers.

## Decision

Use **Auth.js (NextAuth v5)** in the Next.js app for login, session management, and Strava OAuth. The NestJS API validates **JWTs** issued by Auth.js using a custom guard.

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| **Auth.js + NestJS JWT** ✅ | Handles Strava OAuth provider out of the box, session management, free, clean separation of concerns | Two systems to understand; NestJS needs a separate JWT validation guard |
| **Clerk** | Beautiful UI, very easy, great DX | Paid at scale, vendor lock-in |
| **Auth0 / Okta** | Enterprise-grade, comprehensive | Overkill, expensive, vendor lock-in |
| **Custom JWT** | Full control | Reinvents OAuth token rotation, PKCE, session management |
| **Supabase Auth** | Easy if using Supabase DB | Ties auth to DB vendor |

## Consequences

### Positive
- Auth.js handles Strava OAuth2 dance, including PKCE and token refresh, out of the box
- Session cookies managed by Next.js; API is fully stateless
- Clean boundary: web app owns login UI and session; API only validates bearer tokens
- Adding new OAuth providers (Garmin, Google) is a configuration change in Auth.js

### Negative
- Two mental models: Auth.js sessions (cookie-based) on the frontend, JWT validation on the backend
- New developers must understand the token flow between the two apps

### Token Flow

```
1. User logs in via Auth.js (Next.js)
2. Auth.js creates a session and issues a JWT
3. Next.js passes JWT as Bearer token to NestJS API
4. NestJS JwtGuard validates signature and extracts userId
5. All downstream queries are scoped to that userId
```

A detailed token flow diagram should be included in `docs/AUTH_AND_TOKEN_MANAGEMENT.md`.
